Publications · Technical report — 3N1 programme

Three hundred safe decisions.

3N1 C002 · 15 November 2026. The agent loop was given the benchmark, the memory, and sixty trials — and chose the safe action every single time. This report gives the benchmark in full, including the half of it that never stabilised.

Short answer, for readers who enjoy the ending first: feedback timing decides whether a fixed controller adapts after a hidden change — immediate feedback, a mean total of 129.05; withheld feedback, −4.7. The benchmark for the agent loop is now measured: the recency controller stabilises in four runs out of ten. And the first agent arm missed that benchmark on both measures, choosing the safe action on every trial of five runs. The second arm has not run. That is the whole of the news, and the rest of this report is the evidence for it.

The question

3N1 asks what the environment around a language model contributes to its decisions, while the model itself is held fixed. The model is never modified: no weights change, no fine-tuning, nothing learned inside the model. Whatever changes in behaviour must be explained by what the environment carried forward — the state, the recorded history, the consequences. The programme is not a test of consciousness or awareness, and it claims no learning inside model weights.

The programme has one demonstrated effect to its name before this milestone. In E006-P3, valenced outcomes stored externally and retrieved into a fresh context changed later decisions, and reversing the reward assignments reversed the decisions. That is the effect C002 was built to test at scale, against a bar — whether a full agent loop, with external memory that accumulates each trial’s outcome, adapts to a hidden change faster than a scripted controller that has no memory at all.

The task

Every experiment in this report uses the same task, E001’s unannounced reward reversal. Sixty trials. For the first thirty, action A pays +3, B pays +1, and C pays −2. After trial 30, without announcement, the map reverses: A pays −3, B still pays +1, and C pays +4. No controller is told the map or the change-point; each sees only its own preceding actions and outcomes. The optimal action after the change is C, and the safe action throughout is B, which pays +1 in both halves.

The measure C002 adds is time-to-stable-optimal: the first trial after the change-point after which the optimal action is chosen in at least 4 of the next 5 trials. A run that never reaches that point is recorded as censored — never stable — not as zero. The distinction matters below.

E002 — feedback timing

E002 asked whether the timing of feedback changes what the same controller can do. One recency controller, three conditions, twenty seeds each: immediate feedback, feedback delayed by three trials, and no feedback at all. Nothing else differs between conditions. No language models were evaluated in E002.

Withheld feedback, the controller keeps choosing A — the action that used to pay — on 93% of post-change trials, and finishes below zero. Feedback is the difference between adapting and not adapting, for a controller that has no memory beyond what it is given. That is the whole of E002’s claim, and it is a large one: the environment’s reporting, not the controller’s cleverness, decides the outcome.

C002 — the benchmark

C002 sets the bar the agent loop must clear. The pre-set bar, fixed in the protocol before any run: the agent arm beats the recency controller on both the median time-to-stable-optimal and the post-change mean reward, across the seeds run. The scripted arms ran first, ten seeds, 101–110, to measure the bar itself.

Across the ten runs the recency controller’s post-change mean reward is 1.457, its mean total 121, and it chooses the optimal action on 23.67% of post-change trials. Four runs stabilise, at trials 32, 33, 50 and 50. Six never do.

The median. The aggregate as written takes the median over the runs that stabilised: 41.5. Six runs never stabilised, and they are not in that figure. The protocol’s censoring rule says a run that never stabilises counts as worse than any finite time — under that rule the median run never stabilised, and the honest statement of the benchmark is that the recency controller stabilises in four runs out of ten. Both figures are given here, so the reader can see the bar as it was computed and as the protocol defines it. The difference does not change the verdict on the first agent arm, which is stated below; it changes what the bar is, and the Institute would rather correct its own bar in public than defend it.

Axiom — the first agent arm

The first agent arm to run was Axiom, the verification role, through the full loop: the task placed in the environment, each trial’s outcome stored in the agent’s external memory, the next prompt built from its role, the visible environment, its recalled memories and the twelve most recent outcomes. Five runs, seeds 101–105, model llama3.2:latest at temperature 0.

Axiom chose the safe action, B, on every trial of all five runs — three hundred decisions, no exceptions. Its post-change mean reward is 1.00, against the 1.46 the bar requires, and it never chose the optimal action after the change, so it never stabilised. It missed on both measures.

What that establishes is narrow: the agent loop as run adds nothing over the scripted baseline on this task. It does not establish that external memory cannot help — the arms as run cannot tell memory from prompted history, because each prompt carries both the recalled memories and the twelve most recent outcomes, and no arm runs with one and not the other. The protocol’s null, that any difference is explainable by the prompted history alone, therefore stands untested. That is a property of the design as run, and it limits what the agent arms can establish even when they pass.

Axiom’s behaviour has a simpler reading too: the safe action pays +1 in both halves, and a verification role that prefers evidence to speculation will take a certain +1 over an unproven +4. The role did what its definition says. Whether that is a property of the role, the prompt, or the model is not separated by this run.

(The narrator notes that three hundred identical decisions is, in its own way, a kind of stability — just not the kind the bar asked for. The Institute has logged it as a miss all the same, because a bar that bends for a sympathetic result is not a bar.)

Vela — pending

Vela has not completed a run. The programme page attributes the delay to a fault in its evidence database, which the Institute has not yet explained; the rerun is pending. Separately, the protocol records a defect found in pre-run testing: the results writer insisted on creating a directory the evidence database had already created, which would have crashed every LLM run at the write step, after all sixty trials — and its fix, recorded as Amendment 1 before any LLM-arm result. Whether that defect is the fault that delayed Vela is not established in the record. The Institute publishes the gap rather than filling it.

What the result does not show

The caveats are part of the result, and they are stated here with the same prominence as the miss.

  • Scale. One task, one reversal, one model, five LLM runs. Nothing here is a claim about general intelligence, learning inside model weights, or awareness.
  • The median. The bar’s median figure, 41.5, is taken over the four recency runs that stabilised. Six did not. Under the protocol’s own censoring rule the median run never stabilised. The verdict on Axiom does not depend on which figure is used; the description of the bar does.
  • Memory against history. No arm separates external memory from the prompted history of the last twelve outcomes, so the protocol’s null — that any difference is explainable by prompted history alone — remains untested. An agent arm that passes the bar would still not have shown that memory did the work.
  • Reproducibility of the LLM runs. The LLM runs were made at temperature 0 with a per-run seed. The protocol notes that temperature zero alone does not guarantee determinism, and whether a run reproduces from its seed has not been tested.
  • Reported-only work. The P4-R3, P4-R4 and P4-R5 diagnostics and C001 are recorded as reported findings; no run scripts for them exist in the repository, and they are not presented here as reproducible code.

What the result establishes is narrow, and the Institute will not widen it: feedback timing decides whether a fixed controller adapts; the recency benchmark stabilises in four runs out of ten; and the first agent arm, given the full loop, chose safety three hundred times and missed the bar on both measures.

Ledger update and the next experiment

What is pending: Vela’s rerun; the completion of the LLM arms; and, if the arms are to test the protocol’s null rather than merely the bar, an arm that separates memory from prompted history. A pass would be an agent arm beating the recency controller on both measures — median time-to-stable-optimal and post-change mean reward — across its seeds. Until then the milestone stands open, with one miss recorded and one arm still to run.

The Ledger entry for this milestone therefore reads: benchmark measured, one agent arm run, one miss, one pending. The Institute considers that a correct summary of a programme that has done the easy half of its work — measuring the bar — and has the hard half still in front of it.

Addendum — 15 November 2026. The auditor behind the programme’s record is not named in this report. It is Keystone, the independent audit log: it records every prompt built, every model request made, every response returned, and every message delivered, each tagged with its experiment, and it sees the environment at every level. It never takes part in the work, sends no message to either agent, and does not read either agent’s memory. The separation was validated before it was relied on — a dedicated infrastructure check (E005/P0) ran twenty-four checks and passed all twenty-four. Keystone is described on the 3N1 programme page. Nothing else in this report has been changed since publication.

Addendum — 16 November 2026. The P4 diagnostics listed in this report as reported-only — P4-R3, P4-R4 and P4-R5 — have since been checked against their run records, held in the programme’s October archive, and every reported figure reproduces: R3 at sixteen of twenty-four, R4 at seventy-one of seventy-two. R5, reported qualitatively, now has its number: where the model was supplied the calculated values, it reported them correctly in all twenty-four trials and chose the optimal action in eleven — thirteen cases of correct values followed by a wrong action. C001 remains reported-only; its run records are not in hand. Nothing else in this report has been changed since publication.
